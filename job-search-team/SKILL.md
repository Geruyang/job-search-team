# 求职智能体小组

将真实履历、可调策略、岗位证据和可核验回执连起来。只做用户当前请求的环节；筛选不自动授权聊天或投递，安装技能不等于创建定时任务。技能触发时执行下列启动流程，而不是仅告诉用户如何做。

## 宿主与模型适配

本技能使用通用Markdown指令、JSON配置及独立脚本，不绑定模型提供方、智能体框架或专属工具名。支持技能目录的宿主加载本目录；其他宿主可把本文件作为任务指令，并按链接加载引用文件。调用语法和安装目录由宿主决定，不要求固定的命令前缀。

在线执行需要宿主具备本地命令执行、文件读写，以及可访问已登录浏览器扩展的环境。可通过宿主提供的终端工具、受控执行器或用户本机执行这些脚本。只有文本能力的模型仍可处理提供的JD、配置和证据，但不能声称已启动助手或操作网站；无本地执行能力时给出待执行命令及所需回传信息。多智能体能力可选，单模型可按角色顺序执行同一流程。助手当前支持BOSS直聘、猎聘及兼容扩展的Chromium浏览器；模型可替换不代表自动支持所有招聘网站或浏览器。

## 启动与配置

首次导入或换电脑，先读 [全新环境安装与验收](references/setup.md)。技能目录、工作区和助手目录是三个独立位置；随包文件相对于本技能目录解析，不从当前终端目录猜路径。运行依赖只有Node.js >=22和兼容浏览器，无Python、npm依赖包或原项目文件要求。

1. 读取用户指定工作区中实际存在的规则、履历、偏好和授权；新工作区先由用户提供个人履历与目标，不假设有历史文件。不要沿用其他批次的账号、配额、发送时间或授权。已有受保护文件不可覆盖；新简历在本轮工作区新建版本目录，路径由当前任务约定。
2. 读取 [策略配置](references/policy.md)，将 [配置模板](assets/policy-template.json) 复制到本轮目录。展示评分权重、否决条件、HR活跃和岗位更新时间这四组配置，集中请用户确认或重新提供；本轮已有明确答案则直接记录，不重复询问。允许逐项启用、关闭和替换；用户说“沿用”时记录所沿用的具体版本。配置未确认可先收集事实、建立助手和试算，不按未确认门槛最终淘汰或外发。
3. 对涉及在线查找、筛选补证、聊天或投递的任务，立即读取 [网页助手搭建和使用](references/browser-assistant.md)，执行跨系统的 `node scripts/ensure-assistant.mjs --workspace <工作区>`，自动复用或创建本机助手。Windows也可使用 `scripts/ensure-assistant.ps1`。不能仅在文档中引用原项目路径；完整干净源码已随技能附带。纯离线评分无需启动浏览器。
4. 助手已连接则核对真实账号、所选标签、权限及快照；未连接则恢复配对。首次扩展安装、登录或安全验证若受到工具限制，明确给出唯一必要的用户操作，完成后继续。不得宣称安装技能即可绕过浏览器首次加载限制。
5. 读取 [团队运行协议](references/team.md)，按任务规模启用角色。单平台无需启动另一团队，只有获准修改简历才启用资料写入任务。由用户选择模型或使用当前宿主可用模型；岗位评估优先分配较强推理能力，采集与资料核对可用轻量模型，不要求专有推理参数。用户明确指定的模型不可用时报告，不静默替换。

## 筛选流水线

- 以3–5岗小批次执行：实际搜索和完整JD → 实际用人主体分类 → 用户规则硬筛 → 有证据的维度评分 → 分组比较 → 材料准备 → 获准外发时认领/历史核验 → 单次执行 → 回执对账。
- 搜索使用助手读取真实可见列表及详情，核对城市、关键词、分页和实际链接。不以全国列表中挑出某城市冒充设置过该城市筛选。用工评价、行业和生活成本需当前公开来源；搜索摘要仅为线索，记录来源/时间/主体，不编造网页研究。
- 评分0–5、0.5刻度，未知 `null`。完整总分仅在所有正权重适用项已知时生成；否则保留已知分、未知权重及范围。使用 `node "<技能目录>/scripts/score.mjs" "<评分输入JSON>"` 统一算分，匿名三维附加 `--anonymous`。输入结构见 `assets/score-example.json`；示例数据不能当作真实岗位评估。不同评分配置、五维与匿名三维分别排序。
- 硬筛默认沿用v3.1语义：只有充分证据触发才否决。未发现触发证据与已核实未触发明确区分；缺证不自动补分。用户可以改此语义，但必须记入本轮配置。
- 年限只影响匹配，不独立否决，不在多维重复扣分；真实独立技能/学历/资格仍核对，不能将年限要求换名为技能门槛。
- HR活跃、职位更新时间、职位发布时间、公司页面更新时间分别记录。按用户选择的时间字段、窗口、未知处理及优先/硬筛模式执行，详见策略配置。
- 每个优先/替补岗位交付：两项直接匹配证据、最大缺口、选择原因、可能改变判断的新信息；资料不足者不宣称全池严格总分最优。

## 外发与交付

外发前核对账号、当前岗位及JD、相同需求的跨站历史、认领、已授权配额、附件版本及语言。已有明确授权持续有效，不逐条重复询问；没有授权只准备草稿。话术突出真实的两项能力和可贡献成果，不发内部负评或评分缺口；被问到经历如实回答。

已投、已联系、被拒、提交结果未知的同一需求不自动重发；未知先对账。BOSS锁定附件只计沟通，猎聘附件与介绍分别记结果。负回执优先，点击成功或输入框清空不算送达。具体站点问题与稳定操作见网页助手文档。

本轮落盘 `policy.json`、`jobs.json`、`evaluations.json`、`claims.json`、`receipts.json` 和简短结果；小任务可合并文件但保留配置版本、来源、未知项和动作状态。队长单写平台台账、总协调单写跨站认领。输出实际完成数、仅沟通/投递/失败/待核数量及证据路径，不以计划数代替完成数。

该技能来自本项目2026-10-30以前的实践，来源及冲突取舍见 [来源](references/provenance.md)。历史故障不是永恒的平台结论；每轮以当前页面和工具实际返回为准。
