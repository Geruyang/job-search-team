# 求职智能体小组

将真实履历、可调策略、岗位证据和可核验回执连起来。只做用户当前请求的环节；筛选不自动授权聊天或投递，安装技能不等于创建定时任务。技能触发时执行下列启动流程，而不是仅告诉用户如何做。

## 宿主与模型适配

本技能使用通用Markdown指令、JSON配置及独立脚本，不绑定模型提供方、智能体框架或专属工具名。支持技能目录的宿主加载本目录；其他宿主可把本文件作为任务指令，并按链接加载引用文件。调用语法和安装目录由宿主决定，不要求固定的命令前缀。

在线执行需要宿主具备本地命令执行、文件读写，以及可访问已登录浏览器扩展的环境。可通过宿主提供的终端工具、受控执行器或用户本机执行这些脚本。只有文本能力的模型仍可处理提供的JD、配置和证据，但不能声称已启动助手或操作网站；无本地执行能力时给出待执行命令及所需回传信息。多智能体能力可选，单模型可按角色顺序执行同一流程。助手当前支持BOSS直聘、猎聘及兼容扩展的Chromium浏览器；模型可替换不代表自动支持所有招聘网站或浏览器。

## 初始化：资料与授权 → 助手 → 登录 → 验收

首次使用、换电脑或更换账号时，先读 [初始化与授权](references/initialization.md) 和 [安装与验收](references/setup.md)，按以下次序实际执行。已提供的有效资料和授权直接复用，只补缺项。

1. **用户资料和配置。** 要求用户私下提供本轮简历及可用附件版本、目标岗位和城市、各维度评分占比、否决项及缺证处理、时效规则。比例与条件不能继承作者个人设置；模板只是待确认示例。核验履历事实，保护原件，未获授权不改简历。
2. **逐类授权。** 确认本地部署、安装扩展、站点与账号范围、读取/截图、自动切页与前台显示、聊天/默认问候/附件/平台联系信息按钮、资料修改、配额和停止条件、数据保留与公开范围。填写 [初始化模板](assets/initialization-template.json)；授权可逐项拒绝，不要求为筛选授予全部权限。既有明确授权不重复问，工具或平台限制不能自行绕过。

   首次使用时建议用户授权在其私有工作区创建**本地解决方案知识库**，记录自动求职的问题、尝试、有效办法、未解决边界和人工干预。已有授权直接建库/复用；用户不创建也正常使用，说明跨会话经验依赖模型可用记忆及用户提供的记录，不保证完整保留。知识库不作为使用技能的前置条件，详见 [经验知识库](references/solution-knowledge.md)。
3. **编写、适配并安装助手。** 读取 [网页助手协议](references/browser-assistant.md)，以随包完整源码搭建独立本机插件，运行 `node scripts/ensure-assistant.mjs --workspace <工作区>`。已有兼容助手优先复用；需改动时保留原配置，测试新副本再升级，不能覆盖在途任务或复制旧用户配对。没有现成适配时按协议开发并验证，不声称仅写完源码便安装成功。
4. **用户登录。** 安装加载与权限生效后，由用户在同一浏览器登录招聘平台、完成验证码。助手只核对正确账号、所选页面与授权，不索取密码、Cookie或登录令牌。环境允许的操作自行执行，仅将确实需要用户在场的步骤交给用户。
5. **尽可能全面验收。** 按 [功能验收表](references/acceptance.md) 覆盖连接、标签发现、权限撤回、读取、评分、导航/填写/点击、截图与切页、聊天及附件回执。模拟测试和真实站点测试分别记结果；真实外发只在获准的实际任务中验证，不能为测功能随便发消息或投递。未测、失败、受限均明确记录，不能承诺所有功能已通过。
6. **进入任务。** 先核当前任务是否暂停，再读最新政策、知识库索引及与本次故障相关案例；有库时每轮启动及故障恢复前优先参考，结合当前版本/页面验证，不机械重放旧动作。确认配置和可用能力后，优先处理平台回复、附件请求，再推进获准投递和筛选。读取 [团队协议](references/team.md)，按用户需求和宿主能力顺序或分工执行，不强制专有模型或工具。

纯离线评估仅完成资料、策略和所需验收，不强迫安装或登录；只有文本能力的宿主不宣称已操作网页。运行依赖为 Node.js >=22 和支持本地扩展的桌面 Chromium 浏览器，全部路径相对于本技能或用户选定工作区。

## 筛选流水线

- 以3–5岗小批次执行：实际搜索和完整JD → 实际用人主体分类 → 用户规则硬筛 → 有证据的维度评分 → 分组比较 → 材料准备 → 获准外发时认领/历史核验 → 单次执行 → 回执对账。
- 搜索使用助手读取真实可见列表及详情，核对城市、关键词、分页和实际链接。不以全国列表中挑出某城市冒充设置过该城市筛选。用工评价、行业和生活成本需当前公开来源；搜索摘要仅为线索，记录来源/时间/主体，不编造网页研究。
- 评分0–5、0.5刻度，未知 `null`。完整总分仅在所有正权重适用项已知时生成；否则保留已知分、未知权重及范围。使用 `node "<技能目录>/scripts/score.mjs" "<评分输入JSON>"` 统一算分，匿名三维附加 `--anonymous`。输入结构见 `assets/score-example.json`；示例数据不能当作真实岗位评估。不同评分配置、五维与匿名三维分别排序。
- 硬筛采用用户确认的证据语义：只有充分证据触发才否决。未发现触发证据与已核实未触发明确区分；缺证不自动补分。用户可以改此语义，但必须记入本轮配置。
- 年限只影响匹配，不独立否决，不在多维重复扣分；真实独立技能/学历/资格仍核对，不能将年限要求换名为技能门槛。
- HR活跃、职位更新时间、职位发布时间、公司页面更新时间分别记录。按用户选择的时间字段、窗口、未知处理及优先/硬筛模式执行，详见策略配置。
- 每个优先/替补岗位交付：两项直接匹配证据、最大缺口、选择原因、可能改变判断的新信息；资料不足者不宣称全池严格总分最优。

## 外发与交付

外发前核对账号、当前岗位及JD、相同需求的跨站历史、认领、已授权配额、附件版本及语言。已有明确授权持续有效，不逐条重复询问；没有授权只准备草稿。话术突出真实的两项能力和可贡献成果，不发内部负评或评分缺口；被问到经历如实回答。

已投、已联系、被拒、提交结果未知的同一需求不自动重发；未知先对账。BOSS锁定附件按原始状态登记，猎聘附件与介绍分别记结果。用户可约定“附件请求已发送”计入送达统计，但必须保留 `request_sent` 原始回执与接收/查看状态未知，不能冒称对方已接收或已读；统计口径见 [初始化](references/initialization.md)。负回执优先，点击成功或输入框清空不算送达。猎聘按本轮用户约定先介绍后附件；默认问候可能自动外发，需在初始化明确是否允许。所有智能体自写文字按配置附加来源标记。具体站点问题与稳定操作见 [故障复用](references/troubleshooting.md)。

## 招聘者意向与每20岗复查

每次检查或处理聊天，同时依据准确原会话更新招聘者态度、证据及观察时间，记录有兴趣的岗位并在结果中展示重点岗位、积极信号和下一步。自动问候、已读或平台推荐不等于HR有兴趣；最新拒绝覆盖旧积极信号。详细分类及文件格式见 [意向跟踪](references/recruiter-interest.md)。

每累计成功联系/投递 **20个岗位（仅打招呼也计）**，在继续下一批前复查态度仍不明确的岗位。按平台+真实需求去重，介绍、附件及重试不重复计岗；累计游标跨轮次持久化。自首次成功沟通超过3日、已读且一直无HR回复，或已超过7日的待定岗位退出例行复查；以后有新消息仍优先处理。复查为读取，不自动发催问或重复材料。使用 `node scripts/plan-attitude-review.mjs <跟踪JSON> [--now <ISO时间>]` 规划，完成读取/记录后才推进检查点；暂停时仅记录待办。历史不完整不得由介绍/附件总数反推已联系岗位数。

本轮落盘 `policy.json`、`jobs.json`、`evaluations.json`、`claims.json`、`receipts.json` 和简短结果；小任务可合并文件但保留配置版本、来源、未知项和动作状态。队长单写平台台账、总协调单写跨站认领。输出实际完成数、仅沟通/投递/失败/待核数量及证据路径，不以计划数代替完成数。

V2.0基础上于2026-11-04增加本地经验知识库、招聘者意向与20岗复查。原始实践来源见 [来源](references/provenance.md)。通用技能不包含个人简历、账号、真实聊天或私有案例；历史故障不是永恒的平台结论，每轮以当前页面和工具实际返回为准。
