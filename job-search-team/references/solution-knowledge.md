# 本地解决方案知识库

首次初始化建议并询问是否在用户私有工作区建库；记录授权来源、保存位置和保留要求。已经授权不重复询问。拒绝建库不阻止技能使用，不擅自创建替代经验库；说明以后可参考的历史取决于模型可用记忆和用户另行提供的资料。任务必需的提交回执/防重记录按独立数据授权处理，不冒充用户同意长期经验留存。

建议目录为 `<私有工作区>/解决方案知识库/`，不固定个人机器路径。最小结构：

- `README.md`：关键词索引、当前规则优先级、最新可复用案例和未解决项。
- `incidents.jsonl`：每行一个案例或带同一ID的状态更新，追加/合并去重。
- `人工干预记录.md`：可与案例合并，区分用户手动发信、发送简历、电话作答、恢复窗口、权限操作及接管邀约。

每条案例至少记录：`id / occurred_at或unknown / platform / symptom / environment_version / attempted_steps / outcome / evidence_refs / human_intervention / reusable_method / limits / status / updated_at`。`human_intervention`说明谁做了什么、由何证据确认、是否解决，不能把用户动作计入智能体成果；未发生记none，未知记unknown。状态建议 `verified / user_confirmed / partial / unresolved / superseded`；把事实、用户反馈和推断分开。

**实际使用：**

1. 每轮启动先读索引、当前授权与最近未决项，再有针对性读取相关案例；不要反复载入全部聊天历史。
2. 遇同类问题先检索症状/平台/错误/版本，确认方法仍符合当前授权和页面；旧桌面操作不覆盖当前仅助手限制。
3. 先核在途与unknown，再尝试当前安全可用的正常恢复。不可借“经验”重试未知提交、穿透遮挡或规避工具拒绝。
4. 故障解决、失败、用户纠正或人工接管后更新案例；回合结束补充尚未解决项和下次入口。不能仅写“重试成功”，要记录有效步骤及验证凭据。
5. 经验过时则标superseded并链接新结论，保留旧事实；“恢复后出现回执”不自动证明恢复动作触发了发送。

隐私：保存必要摘要及本地证据指针，避免复制完整简历/聊天/联系方式。Cookie、配对密钥、身份证号不入库。知识库默认不进公开仓库、发布包或技能目录；通用技能只提炼匿名方法。相对路径应以知识库目录解析。新用户不得继承作者个人案例、否决项或权限。
