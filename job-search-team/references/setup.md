# 新电脑安装和首次验收

## 文件与环境

完整解压技能ZIP，保留SKILL.md、references、scripts、assets的相对位置，不能只上传SKILL.md。技能目录可放在任意位置，也可只读；助手和本轮数据写入另选的可写工作区。不要移动已经加载到浏览器的扩展目录，否则需要重新选择扩展位置。

必须准备：

- Node.js 22或更高：用 `node --version` 确认。缺失时通过官方网站或系统软件管理器安装并重新打开终端。全部运行代码只用Node内置模块，无须npm install、Python或其他项目。
- 支持Manifest V3及加载本地扩展的桌面Chromium浏览器，如Chrome或Edge。移动浏览器、不支持扩展的内嵌页或受组织策略限制的浏览器不能保证适用。
- 浏览器与助手服务在同一台电脑、同一本机网络环境中，允许127.0.0.1回环连接。默认端口17373；容器、WSL、远程沙箱的127.0.0.1通常不等于桌面电脑，应在浏览器所在系统运行Node。
- 用户自己的招聘账号、登录验证、履历和求职条件，技能包不包含个人资料。

任意LLM都能理解本技能。自动执行还要求宿主能在这台电脑调用命令、读写文件，或有用户允许的本机工具连接。只有云端聊天或文件上传能力的宿主不能直接控制本机助手：需要用户执行本机命令并回传结果，或接入宿主支持的本机工具。不要把监听地址改为公网来绕过这一环境差异。

## 从零部署

1. 用系统文件管理器新建可写工作区，例如自己的“求职工作”文件夹，记下绝对路径。启动器要求工作区已存在，里面不需要预先放任何项目文件。
2. 替换下面两处占位符，保留路径两侧双引号；可从任意终端目录执行：

```sh
node "<技能目录>/scripts/ensure-assistant.mjs" --workspace "<工作区绝对路径>"
```

3. 启动器从随包源码复制到工作区 `.job-search-assistant/browser-bridge`，启动本机服务并生成新配对。输出bridgeRoot（助手目录）、extension（扩展目录）、pairingFile（配对文件）的实际路径。尚未连接扩展时connected=false正常。
4. Chrome打开 `chrome://extensions/`，Edge打开 `edge://extensions/`，开启开发者模式，选择“加载已解压的扩展程序”，加载输出的extension目录。宿主工具或组织策略禁止此操作时需用户完成或选择允许的浏览器，不绕过限制。
5. 点击扩展图标打开“简历网页助手”面板，导入输出的pairingFile并连接。文件位于隐藏目录时用文件选择器的完整路径输入功能；macOS可用前往文件夹。不要将配对内容发进对话。
6. 同一浏览器中登录招聘账号并打开所需页面。面板0.2版会默认选择发现的招聘标签，核对账号，只保留本轮目标页权限，并保持面板打开。
7. 用输出的bridgeRoot做只读验收：

```sh
node "<bridgeRoot>/cli.mjs" health
node "<bridgeRoot>/cli.mjs" status
node "<bridgeRoot>/cli.mjs" tabs
node "<bridgeRoot>/cli.mjs" snapshot <实际返回的标签ID>
```

服务响应、connected为真、标签及权限正确、snapshot读到正确账号和正常招聘页面，四项都确认才认为可用。未连接时不要连续提交会等待超时的页面任务；验证码由用户完成。服务启动不能代替浏览器读写验收。

8. 将assets/policy-template.json复制进本轮目录，提供自己的履历并确认四类筛选配置。先筛选，具备明确授权才沟通投递，按 [网页操作协议](browser-assistant.md) 查重和核验回执。

## 计分与日常复用

随包示例用于安装检查，不是真实职位：

```sh
node "<技能目录>/scripts/score.mjs" "<技能目录>/assets/score-example.json"
```

应得到完整分null、已知分68、未知权重15、范围[68,83]。实际评估换成同结构的真实输入；匿名三维加 `--anonymous`。

下次用同一启动命令复用服务和配对，无须重复解压或覆盖助手。指定已有安装时加 `--bridge-root "<已有助手目录>"`。端口被别的服务占用时不关闭它；全新实例可加 `--port 17374` 使用空闲端口，再导入该实例生成的新配对。已有配对端口不能随意改动。

宿主回收后台进程时，可在独立本机终端运行 `node "<bridgeRoot>/server.mjs"` 保持服务（默认17373），不要同时启动两个实例。自定义端口继续使用启动器或按shell设置RESUME_BRIDGE_PORT，与配对保持一致。面板“停止连接”只停止新任务，已派发动作先对账。系统重启后重新执行启动器。

## 换电脑与排障

- 新电脑只复制技能ZIP。旧电脑.local、session、令牌和标签ID不迁移；用户选择的履历及投递历史可另行提供以便事实核对与查重。
- 无原工程、外部技能、固定模型SDK要求；空工作区即可搭建。
- Node找不到：安装后重开终端、核对PATH。回环受限：检查本机权限及执行位置，不在云端反复访问桌面的127.0.0.1。
- connected=false：保持面板打开，核对服务及当前工作区配对文件。
- 401或配对不符：用显式bridge-root定位当前服务所属目录，或另选空闲端口；不删除旧密钥或杀旧进程试错。
- 标签缺失：核对同一浏览器配置、域名及面板权限。document/ref过期：重新snapshot，不放松守卫。

在技能目录可运行 `node --test scripts/test-score.mjs scripts/test-bootstrap.mjs assets/browser-bridge/tests/*.test.mjs`，需要回环权限，仅使用临时服务和模拟页面。代码跨系统可移植不代表已在所有系统或LLM宿主上实测真实网站，应以新电脑的首次验收为准。
