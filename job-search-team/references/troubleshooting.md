# 可复用故障处理（更新至2026-11-04）

以下来自特定环境实测，区分解决办法与未解决边界；不能从单个案例推断所有浏览器相同。先读用户当前授权、助手队列和新快照，优先平台回复，再附件与新岗位。

| 问题 / 观察 | 最终采用的办法 | 状态与边界 |
|---|---|---|
| 内嵌页能读文字，却无法由独立程序获得可靠后台图像；另一控制通道被反馈引起后续异常刷新 | 使用用户选择的独立Chrome，安装同一助手，在该浏览器重新登录；业务操作和截图统一走助手 | 独立Chrome双站读页与截图曾真实成功；独立隐藏内嵌页截图后端未实现，刷新因果未确证 |
| 截图返回 `Either the '<all_urls>' or 'activeTab' permission is required.` | 确认运行中扩展版本与权限；临时activeTab需目标页用户手势，持续截图采用用户接受的manifest授权；修改manifest后重新加载扩展 | 不能把源码声明当成已授权；只关/开面板不会更新manifest。用户或组织可随时撤销权限 |
| 截图只报泛化错误，无法区分焦点、文档、权限或API失败 | 返回有界的实际浏览器错误并隐藏URL；核对标签、文档和窗口状态，移除不必要的“窗口必须具有焦点”前置要求 | 故障诊断改善；不能把所有超时叫权限问题 |
| 截图调用不返回，占用队列 | 浏览器捕获10秒超时、清理事件监听；回查status确认队列是否释放 | 真实超时曾正常返回且队列空闲；写入超时仍先对账，不能重启后盲重发 |
| 切换双平台后临时截图授权不稳定 | 经用户许可，截图自动切目标活动页；使用已接受的持续截图权限 | BOSS→猎聘→BOSS曾逐张核验成功，不需要每次点扩展图标；不主动刷新 |
| 最小化时返回成功但图像滞后，DOM有弹窗而图像没有；或 `image readback failed` | 核对 `windowState` / `freshnessUnverified`，结合当前会话和DOM；允许时恢复窗口/短暂前台；仍失败按授权文字核验 | 有一次最小化截图成功不代表可靠实时截图。新鲜度标记有模拟测试，首次新安装仍须实机验收；锁屏未验证 |
| BOSS选中简历并提交后，窗口残留、回执未更新 | 不再次点发送；先切回BOSS已有标签并等待，重新快照；必要时经授权短暂前台，查对应会话回执 | 用户多次反馈及后续页面记录支持此恢复路径，不保证每次有效；没有回执仍待核 |
| BOSS出现“附件简历请求已发送” | 保存原始 `request_sent`；用户若选择该口径可计简历送达，接收/查看继续单独记未知 | 统计由用户约定，不自动推断招聘者同意、已读或正式投递 |
| 猎聘聊天侧栏在屏幕外，能读摘要而无法点击 | 激活现有目标页，从正常消息入口重新打开侧栏，再正常滚动和快照/截图 | 曾恢复；不改CSS、不删遮罩、不点隐藏控件 |
| 猎聘“聊一聊/继续聊”自动发默认问候 | 初始化询问是否允许；允许则默认问候后补完整介绍，再按约定发简历；查看旧历史从消息列表进入 | 默认问候不是只读动作。自写消息附用户来源标记，平台生成文本另记，不能伪称可控制其标记 |
| 猎聘会话有简历卡，职位按钮仍写“投简历” | 查“我的投递”，按公司、岗位ID、城市与时间确认，保留会话卡与投递记录两类证据 | 当日两条曾在投递列表确认，无需再次提交；未读不影响提交事实，也不等于已查看 |
| 自动操作与用户手机/手动操作并行 | 发送前读取实时历史和对象，未知先对账，记录动作来源 | 手动发出的简历也用于防重；不冒认成果 |
| 执行工具或平台拒绝具体发送 | 记录未执行原因和范围，不换文本/渠道绕过；处理其他独立获准事项 | 用户一般授权与工具批准不同；恢复必须符合实际权限，不把拒绝写成已发送 |

## 发送前后最小核对

1. 确认平台、账号、招聘者/公司/岗位、当前会话和附件版本；查询历史与在途，按用户当前平台内/跨平台重复规则核重，不默认一律跨站封锁。
2. 按配置核对完整介绍及来源后缀，平台允许且已授权才执行。猎聘先介绍的用户要求不得被旧操作习惯覆盖。
3. 单次操作；BOSS迟滞优先切回目标页，随后核对文字或图像；图片与当前会话不一致时弃用。
4. 分别记录介绍、请求、附件、正式投递、接收与已读；按用户口径统计并注明。不以按钮点击、窗口消失或截图成功证明发送。
5. 不明确则保持待核与认领，不重复提交。图像识别是保底工具，不是绕过页面权限的方法。

## 新增实战边界

- 联系人搜索结果可能处于独立小滚动容器。坐标在窗口内仍可能被主列表覆盖；查看真实滚动祖先和遮挡，正常滚动该容器后取新ref，不改CSS或绕过遮挡保护。
- 侧栏旧未读摘要可能落后于原会话；以准确正文和新回执核对，不据旧摘要重复发送。字段数量上限、虚拟列表首屏均不等于完整历史，未找到不等于从未联系。
- 猎聘侧栏正常导航前后可能一度可见又越出视口，不能将一次恢复声称永久修复。旧会话优先从现有联系人打开；岗位“继续聊”可能发兴趣卡，不当纯读取入口。
- 单次附件点击的桥接成功只是派发ACK，弹窗消失也不是成功。正常导航重开原聊/正式投递可解出部分延迟回执，仍无回执者保留unknown，不换“同意”按钮重投。
- 默认英文、错误同名招聘者、整页其他联系人附件文字都可能造成误判；核当前精确会话、唯一目标语言及对应消息。图片API成功也须核画面与文本一致。
- 程序文件名含“执行”、已有认领、列表“继续沟通”、页脚更新时间、机构人数，分别不能证明已发、已介绍、JD更新或客户规模。完整JD截取要匹配独立标题，不能截断职责内同词；Windows中文文件路径使用标准URL到路径转换。
- 故障与人工干预应写入已获授权的[本地解决方案库](solution-knowledge.md)，明确用户确认/手动发送不属于智能体成果。旧办法不覆盖当前权限；没有证据不归因于缺权限、焦点、双击或事件可信度。
