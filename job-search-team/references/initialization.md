# 首次初始化与权限约定

按“用户提供资料和规则 → 记录所需授权 → 编写/适配并安装助手 → 用户登录 → 功能验收”执行。不是每次启动都重新问一遍；已有明确且仍适用的信息直接复用，变更只更新相关项和版本。

## 一次收集的内容

请用户通过本地文件或私有会话提供：

- 简历、可发送附件的路径/版本/语言，以及可公开的项目材料。明确正式工作、科研和个人项目，未证实经历不写入介绍。原件保留，获准修改时另建版本。
- 目标城市、岗位方向、薪资/工时/公司规模等要求及软偏好；实际雇主、猎头和外包关系的处理办法。
- 各评分维度占比及定义。默认五维仅为示例，用户可换维度；非负、总和100%，比例可说明归一结果；未知不补中性分。
- 一票否决项、AND/OR关系、关联公司是否覆盖、证据标准、未知时保留/待核/排除；明确可以没有否决项，不把作者个人排除名单带入新用户。
- 招聘者活跃、岗位更新/发布的独立规则；目标数量和任务范围（仅筛选/沟通/投递/处理回复）。
- 两类或更多岗位介绍模板、事实核对依据、语气、是否带表情、智能体来源标记及平台默认问候是否允许。内部缺口用于评估，介绍突出真实优势；直接提问如实回答，不虚构经历。

复制 `assets/policy-template.json` 和 `assets/initialization-template.json` 到本地任务目录，填入本轮确认值、依据与时间；详细维度、计算方式和证据规则见[策略配置](policy.md)。未确认的模板门槛不用于淘汰或外发。

## 按需要记录权限

权限有三层：用户对任务的授权、宿主执行工具的权限、浏览器/网站权限。用户授权不自动授予另外两层；工具可操作也不代表允许发送简历。

| 权限组 | 应约定的范围 |
|---|---|
| 部署 | 本机文件、Node服务、扩展安装/更新；端口与工作区；不默认创建开机启动或定时任务 |
| 页面读取 | 平台、浏览器配置和账号、目标标签；历史与JD读取；不索取密码/Cookie |
| 图像 | 本地截图、图像分析、自动切换活动页、短暂前台分别授权；如涉及外部图像服务需额外说明数据去向 |
| 页面操作 | 搜索、导航、填写、点击与刷新；未知提交期间不刷新或重放；不可用时如实降级 |
| 对外沟通 | 主动问候、平台默认问候后补介绍、处理主动招呼/回复、婉拒不匹配岗位、附加来源标记 |
| 简历 | 哪份附件、哪些收件人/岗位范围、是否先介绍、回复后主动发送、同意对方请求、次数/停止条件 |
| 联系方式 | 是否允许平台手机号/微信按钮；证件号等敏感字段单独限制；不把读取简历当作可公开所有字段 |
| 资料与数据 | 是否编辑简历、备份/保存位置、保存周期、能否上传第三方；公开发布不包含个人资料与运行证据 |

可以批量授权且跨后续操作持续有效，不要求对已授权的每个岗位重复询问。必要的用户选择与权限申请一次集中说明。没有获准的项目留 `false` 或 `null`，不靠沉默、超时或“有全部权限”猜测新账号/无关用途。

平台限制、验证码及执行工具拒绝不绕过；记录具体未执行动作，继续不受影响的任务。确实需进一步批准时给出可审阅的对象与内容，不能让用户反复进行无诊断依据的重载。

## 回执与统计口径

原始事实和用户统计口径分开保存：

- `request_sent`：平台明确附件请求已发送。
- `attachment_sent`：明确附件卡/附件发送回执。
- `application_confirmed`：平台正式投递记录确认。
- `unknown` / `failed`：结果未确认或明确失败。

用户可指定 `delivery_counting = request_sent_or_attachment_sent`，将“附件请求已发送”计作简历送达；否则按约定的附件回执口径计数。报告注明采用的口径，保留原始状态。任何口径都不能把请求已发送说成对方已同意、已下载、已查看或已正式投递。每个需求只计一次，后续从请求转成附件不再累计一份。

用户手动发送的既有事实写入历史防重；未经证据核实，不归为智能体此次发送成果。最新用户指令覆盖对应旧条文，历史回执本身不改写。
